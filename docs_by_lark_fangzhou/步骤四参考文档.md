# 🧠 Phase 2.4: `openclaw_bridge.py` 架构设计文档

## 1. 模块定位与核心职责

`openclaw_bridge.py` 是连接“飞书容器基础设施”与“OpenClaw 记忆大模型”的纯业务逻辑中间件。它与音频处理完全解耦，是一个**无状态、高并发的异步处理模块**。

其核心职责严格限定为三项：
1.  **Auth (鉴权)**：将前端 H5 传来的免登 `code` 置换为可作为唯一主键的 User Identifier (`union_id` 或 `user_id`)。
2.  **Prompt Injection (配置生成)**：读取本地/云端的 Markdown 记忆文件（如 `study-vocab-{id}.md`），组装成严格符合豆包底层 WebSocket 协议的 `StartSession` 配置字典。
3.  **Memory Write-back (记忆持久化)**：通话结束后，接管 `server.py` 传来的 List 格式对话日志，调用 OpenClaw 进行学习状态结算，并写回 Markdown 文件。

---

## 2. 接口抽象与方法定义

建议将该模块封装为一个具有异步 HTTP 请求能力的类 `OpenClawBridge`，推荐使用 `httpx` 或 `aiohttp` 以完美契合 FastAPI 的全异步事件循环。

### 2.1 初始化参数

```python
class OpenClawBridge:
    def __init__(self, feishu_app_id: str, feishu_app_secret: str, memory_dir: str = "memory"):
        self.app_id = feishu_app_id
        self.app_secret = feishu_app_secret
        self.memory_dir = memory_dir # 存放 study-vocab-{id}.md 的目录
        # 建议复用 HTTP 客户端连接池以降低延迟
        self.http_client = httpx.AsyncClient() 
```

### 2.2 核心方法一：鉴权换取身份标识

* **方法签名**：`async def authenticate_feishu_user(self, code: str) -> str:`
* **执行逻辑**：
    1.  调用 `POST https://open.feishu.cn/open-apis/authen/v2/oauth/token` 接口，传入 `grant_type="authorization_code"`, `client_id`, `client_secret`, `code`。
    2.  解析响应体，提取 `access_token`。
    3.  携带该 Token 调用 `GET https://open.feishu.cn/open-apis/authen/v1/user_info`，必须在请求头加上 `Authorization: Bearer <access_token>`。
    4.  解析返回的 JSON，**优先提取 `data.user_id`，若不存在则提取 `data.union_id`**，作为返回值。
* **异常处理**：若 HTTP 状态码非 200，或业务 `code` 非 0（如 `20004` 授权码过期），需抛出自定义的 `FeishuAuthException`，供 FastAPI 返回 HTTP 401 给 H5。

### 2.3 核心方法二：生成豆包会话配置

* **方法签名**：`async def generate_doubao_config(self, user_identifier: str) -> dict:`
* **执行逻辑**：
    1.  依据 `user_identifier` 拼装文件路径，例如 `memory/study-vocab-{user_identifier}.md`。
    2.  读取该 Markdown 文件内容（如果文件不存在，则初始化一个默认的学习计划模版）。
    3.  提取今日需背诵的单词列表及历史对话上下文（最多截取最近 10 轮以节省 Token）。
    4.  组装并返回符合 `5.md` 规范的字典。
* **输出数据结构规范**：必须严格包含 `tts`、`dialog` 等字段，并且 `extra.input_mod` 必须设为 `keep_alive` 以应对前端的静音切换保活逻辑。

### 2.4 核心方法三：对话日志回写与记忆更新

* **方法签名**：`async def analyze_and_save_memory(self, user_identifier: str, dialog_history: List[Dict]) -> None:`
* **执行逻辑**：
    1.  接收 `server.py` 在 `finish_session` 或 30 秒超时断连时传入的 `dialog_history`。
    2.  （可选但推荐）调用 OpenClaw（文本大模型）的 API，将 `dialog_history` 发送给大模型进行“总结与状态结算”，例如提取用户背错的单词。
    3.  将更新后的学习进度和本次对话日志，以 Markdown 格式追加或覆盖回 `memory/study-vocab-{user_identifier}.md` 中。

## 3. 与现有 `server.py` 的集成点 (Integration Plan)

一旦 `openclaw_bridge.py` 开发完成，我们需要在 `server.py` 中移除现有的 Mock 数据，进行真实接入。

**替换点 1：新建连接时的 Mock 替换**
在 `server.py` 的 `msg_type == "start_session"` 分支下：
```python
# 移除旧的：config = await mock_get_openclaw_config(token, current_session_id)

# 替换为真实的 Bridge 调用
try:
    user_id = await bridge.authenticate_feishu_user(code=token)
    # 将 user_id 绑定到当前会话的 manager 中，以便后续使用
    current_user_id = user_id 
    config = await bridge.generate_doubao_config(user_identifier=current_user_id)
except FeishuAuthException:
    await websocket.send_text(json.dumps({"type": "error", "message": "auth_failed"}))
    await websocket.close()
    continue
```

**替换点 2：会话销毁时的记忆回写**
在 `server.py` 的 `delayed_session_destroy` 和 `finish_session` 流程中：
```python
# 找到 TODO Phase 2.4 注释的位置：
manager = active_sessions.pop(current_session_id)
await manager.stop_session()

# 新增记忆回写：异步执行，防止阻塞 WebSocket 主循环
asyncio.create_task(
    bridge.analyze_and_save_memory(
        user_identifier=current_user_id, 
        dialog_history=manager.dialog_history
    )
)
```
