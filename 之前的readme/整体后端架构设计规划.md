# 🧠 OpenClaw + 豆包实时语音 API (Python 中转架构设计文档 - 飞书 H5 专版)

## 1. 架构概述与核心业务流

本项目是一个集成在飞书网页应用（Web App）中的单人语音学习助手（核心场景：英语背单词）。系统采用**纯 Python 中转架构**，为了保证低延迟和服务器高并发，我们将大模型（OpenClaw）的“慢思考”和语音大模型（豆包）的“快响应”在时间线上完全解耦，并将**所有音频的重采样与编解码工作下放至 H5 前端完成**。

**⏱️ 核心业务工作流：**

1.  **通话前（飞书工作台入口）**：用户在飞书工作台点击应用图标打开 H5。H5 调用飞书 JSAPI (`tt.requestAccess`) 静默获取免登授权码，发给后端换取用户身份。**后端必须提取并使用 `user_id`（或 `union_id`）作为 OpenClaw 记忆文件（如 `study-vocab-{user_id}.md`）的主键，严禁使用 `open_id`，以保证未来跨应用的数据互通。** 后端根据身份向 OpenClaw 获取今日学习计划与专属 Prompt 和历史记忆文本，生成带 Token 的 WebSocket 连接配置。
2.  **通话中（H5 网页端 ↔ Python 基站）**：前端直接通过 `wss://` 连接 Python 中转基站，基站透传配置向豆包发起连接。整个通话过程中，H5 负责复杂的音频采集、降采样和流式播放；**中转基站只管转发二进制包和处理文本组装日志，零大模型调用，极低延迟。**
3.  **通话后（中转基站 ↔ OpenClaw）**：通话结束，基站执行优雅断连，并将完整组装后的对话文本（List）交给 OpenClaw 分析，回写到学习进度记忆文件（如 `memory/study-vocab.md`）中。

## 2. 飞书容器与前端工程规范

鉴于飞书网页应用的安全策略及本项目的个人使用场景（**注：本项目仅针对 Android 与 PC 端优化，不考虑 iOS 设备的音频自动播放解锁限制**），需遵循以下工程规范：

### 2.1 协议与环境要求

* **强制 HTTPS/WSS**：飞书容器要求麦克风权限（`getUserMedia`）必须在安全的 HTTPS 环境下调用。前端页面必须部署在 HTTPS 域名下，前后端通信必须使用 WSS (WebSocket Secure) 协议。
* **防后台挂起（Android 息屏/切应用防失联）**：前端需监听 `visibilitychange` 事件。当页面进入后台时，需维持心跳；后端在收不到音频流时，依托 `keep_alive` 模式保持不断连，等待用户重返应用。

### 2.2 前端音频流处理策略 (Web Audio API)

* **上行（采集与预处理）**：**禁止使用 `MediaRecorder`**。前端直接使用 `AudioContext` 结合 `AudioWorklet`（或 `ScriptProcessorNode`），获取原始音频流后，**在浏览器端使用 JS 手动降采样至 16000Hz**，并转换为单声道、16-bit 小端序的纯 PCM 二进制流。**强烈建议：前端必须强制每累积 20ms 数据（即 640 字节）打包发送一次**，以严格对齐官方流式 VAD 最佳实践，降低截断延迟。
* **下行（接收与播放）**：前端接收到后端下发的 PCM 二进制流后，不使用 `<audio>` 标签，而是通过自定义的 `PCMPlayer`（基于 `AudioContext` 的 `AudioBufferSourceNode` 队列）进行流式硬解播放。**🚨 致命注意：豆包下发的 PCM 音频采样率为 24000Hz，前端 `PCMPlayer` 初始化时必须硬编码为 24000Hz、单声道、16-bit 小端序**，否则会导致音频播放严重失真（变调/慢放）。

## 3. 前后端交互规范 (H5 ↔ Python 中转基站)

为了适应复杂的网络环境和降噪需求，前端增加了“麦克风开关”功能。

### 3.1 客户端（H5） -> 服务端（Python）

* **启动通话 (Text)**

    ```json
    {
      "type": "start_session",
      "session_id": "前端生成的唯一对话ID",
      "token": "免登流程后获取的认证Token"
    }
    ```

    *注：中转基站收到后，根据 token 提取 OpenClaw 提前生成好的 `StartSession` 配置，发给豆包。*

* **麦克风状态切换 (Text - 针对 `keep_alive` 模式)**

    ```json
    {
      "type": "mic_status",
      "muted": true
    }
    ```

    *注：带静音按键的交互模式需要在 `StartSession` 配置 `"input_mod": "keep_alive"`，以防止静音期间服务端超时报错。前端静音时停止发送音频流，并发送此 JSON 告知服务端。*

* **发送音频 (Binary)**
    前端处理好的 16kHz PCM 二进制流（每包 20ms / 640 bytes）。

* **主动结束通话 (Text)**

    ```json
    {
      "type": "finish_session"
    }
    ```

    *注：🚨 中转基站收到此指令后，必须执行**优雅断连两步走**：先向豆包发送 `FinishSession(102)` 事件，等待豆包返回 `SessionFinished(152)` 或 `ContextCanceled` 后，再发送 `FinishConnection(2)` 断开底层 WebSocket，防止远端资源泄露或报错。*

### 3.2 服务端（Python） -> 客户端（H5）

* **状态就绪 (Text)**：告知前端连接豆包成功，UI 可切换为通话中状态。
* **下发音频 (Binary)**：直接转发豆包返回的 TTS 二进制音频流（纯 PCM 数据，24000Hz）。

### 3.3 弱网与断线重连机制（高可用策略）

鉴于移动端或网页端复杂的网络波动（如切换 Wi-Fi、进出电梯、设备息屏），系统必须实现前后端协同的断线重连与会话恢复（Session Recovery）机制，绝不能让网络抖动导致用户的学习进度归零。

* **前端（H5）感知与内存挂起**：
    * 通过飞书 JSAPI `onNetworkStatusChange` 与 `onNetworkQualityChange` 实时监听底层网络状态。
    * 一旦检测到断网或 WebSocket 意外关闭，**严禁将未发送的 PCM 音频流写入 LocalStorage**。必须立即挂起 `AudioContext`，将后续采集的音频数据暂存在前端内存（JavaScript ArrayBuffer 队列）中，并向用户展示“网络重连中...”的 UI 提示。
    * 启动指数退避重连机制，不断尝试使用原有的 `session_id` 重新连接中转基站。
* **后端（Python 基站）会话保留 (Grace Period)**：
    * 当中转基站检测到与 H5 的 WSS 连接意外断开（非正常 `finish_session` 指令）时，**切勿立即向豆包发起 `FinishSession`**。
    * 基站必须在内存中将当前会话状态“挂起”，维持与豆包的底层连接，并启动一个 30 秒的“宽限期（Grace Period）”倒计时。
* **会话恢复与销毁分流**：
    * **成功重连**：若前端在 30 秒内携带原 `session_id` 成功重新建联，基站直接将新 WebSocket 描述符映射回挂起的会话中，无缝对接豆包。前端此时可将内存中积压的音频队列一次性打包发送。
    * **超时销毁**：若 30 秒倒计时结束前端仍未连上，基站视作会话彻底死亡。此时执行完整的优雅断连流程（发送 `FinishSession` 告知豆包），并强制结算当前对话的文本日志，回写 OpenClaw 记忆文件。

## 4. OpenClaw 接口与数据结构规范

### 4.1 通话前：生成并注入提示词（O/O2.0版本规范）

在 H5 初始化时，OpenClaw 需要在后端生成一份针对此次通话的配置。此配置严格遵守豆包 O/O2.0 版本的接口参数。由于 `dialog_id` 机制较弱，必须使用 `dialog_context` 显式注入历史记忆。

* **生成的数据结构 (Dict) 并存入缓存**：

    ```json
    {
        "tts": {
            "audio_config": {
                "channel": 1,
                "format": "pcm_s16le",
                "sample_rate": 24000
            },
            "speaker": "zh_female_vv_jupiter_bigtts" 
        },
        "dialog": {
            "bot_name": "小爪", 
            "system_role": "你是小爪，一个英语学习助手。今天的学习计划包含单词：abandon, benevolent...",
            "speaking_style": "温柔耐心，像朋友一样聊天",
            "dialog_context": [
                {"role": "user", "text": "上次我背到哪个词了？", "timestamp": 1711345000},
                {"role": "assistant", "text": "你上次学到了 abandon，今天我们继续。", "timestamp": 1711345005}
            ],
            "extra": {
                "input_mod": "keep_alive", 
                "model": "1.2.1.1" 
            }
        }
    }
    ```

### 4.2 通话后：提交对话日志

中转服务将完整拼接好的上下文（即清洗掉 interim 碎片后的准确 ASR 识别结果和完整的模型回复文本）作为 List[Dict] 交给 OpenClaw 分析并回写记忆文件。

```python

  {"role": "user", "text": "开始背单词吧", "timestamp": 1711345000},
  {"role": "assistant", "text": "好的，第一个单词是 abandon", "timestamp": 1711345005}
]
```
